# 工程组织：总合成 + 段落合成

## 为什么不是一个大合成

单合成（280+ 层全部堆在一条时间线上）能出片，但改第 8 个镜头要在 280 层里翻，
渲染也只能整片重渲。分隔成段落合成之后：

- 改一个镜头 = 打开一个 20 层的合成
- 单段预览 / 单段渲染不用等整片
- 定位问题时能立刻判断「是这一段本身错了，还是总合成的时序错了」

这套结构是扁平 MG 的通行做法（总合成只做时间线，一个段落一层），也是审片时最容易
定位问题的形态。

## 结构

```
总合成 (45.000s / 50fps / 20 层)
├── 01 开场        21 层   WA 0.00 + 5.60
├── 02 反转        30 层   WA 5.60 + 3.70
├── 03 三步骤     24 层   WA 9.30 + 4.40
├── ...
├── 12 结尾        21 层   WA 37.80 + 7.20
└── 音频层 × 11（VO_01 … VO_12 + BGM）
```

- **总合成只放段落层和音频**，不放任何图形。
- **每个段落合成自带宽高 1920×1080 和完整时长**（与总合成等长或更长），
  内部用绝对时间，靠元素自身的透明度包络控制显隐。
- **段落层 `startTime = 0`，用 in/out 决定显示区间。** 因为段内就是绝对时间，
  层在总合成 `t` 时刻显示的是源合成 `t` 时刻的画面，不会错位。
- 每段设 `workAreaStart` / `workAreaDuration`，双击即定位到该段，单段渲染也只出这一段。

## SHOTS 表

构建器用一张表驱动全部段落，改顺序只是改这张表：

```python
# (名称, 旧起点, 旧止点, 新起点, 新止点, 构建函数)
SHOTS = [
    ("01 开场",      0.00,  7.00,  0.00,  5.60, shot1),
    ("02 反转",      7.00, 11.60,  5.60,  9.30, shot2),
    ("03 三步骤",  11.60, 18.20,  9.30, 13.70, shot3),
    ...
]
```

旧时间轴 = 剧本/配音最初算出来的时长；新时间轴 = 交付规格要求的时长。
关键帧全部按**旧时间轴**书写，注入时由 `T(t)` 换算——这样改交付时长不用动任何 shot 函数。

每段注入时带三个常量：

```javascript
var TM_B = 旧起点, TM_S = 新起点, TM_K = (新止-新起) / (旧止-旧起);
function T(t){ return TM_S + (t - TM_B) * TM_K; }
```

`T()` **只在 `kf()` 里调用一次**（见 pitfalls #12）。

## 时长预算

先做配音，用实测时长反推镜头长度，不要先定时间轴再塞台词：

1. TTS 逐句生成 → `ffprobe` 量每句秒数 → 累加得旁白总长
2. 旁白总长 × 1.2 ≈ 成片时长（留呼吸）
3. 若超规格（例如 45 s），两条杠杆：**删纯过渡镜**（最快见效）、**删/合并段落**；
   最后才调语速（+10%~+15% 仍自然，再快就假）

45 s 的一条实例：12 句 63 s → 删过渡页 + 合并价值观镜 + 语速 +15% → 10 句 36.5 s，
成片 45.0 s 正好。

## 命名

- 段落合成：`01 开场`、`08 特写` —— 两位序号 + 中文短语，AE 里按名排序就是时间顺序
- 图层：`S08_head`、`S08_finger` —— 段落号前缀，跨合成也能一眼认出归属
- 素材项：`rrect_340x4_r2_b2e3f7.png` —— 尺寸 + 圆角 + 颜色，天然去重键

## 迁移一个手工工程的注意点

用户手改过的工程**不能重建覆盖**。要改代码时：

1. 先把工程复制一份 `*_bak.aep`
2. 用 `scripts/inspect_aep.py` dump 出他改了什么（对比 `startTime / inPoint / outPoint / 图层名`）
3. 把改动反向写进 `build_*.py`，保证下次重建不退回旧状态
4. 出片直接渲**他的文件**，不渲染重建版
